# taurus-x 方案（第一版）

> 状态：已确认，已授权编码（不含 commit/push）。

## 1. 目标

`taurus-x` 是一个 Go 编写的命令行脚手架。执行一次 `taurus-x new <项目名>`，交互式勾选组件后，
生成一个 **Go 后端 + Vue 前端** 的完整项目。生成后的形态以
`/Users/yelei/data/code/repos/admin` 为参照，但只保留"基础后台底座"，不含任何 CRM/订单/财务等业务模块。

生成完成后应做到：`go build` 通过、`pnpm build` 通过、配上 MySQL/Redis 后能登录后台，
看到用户/角色/权限/部门/日志等菜单。

## 2. 已确认的决定

| 项 | 决定 |
|---|---|
| 交付形态 | Go CLI，模板用 `embed` 打进二进制，单文件分发 |
| 与 taurus-pro-core 的关系 | 独立新做；core 保持不动。可选组件的初始化写法参考 core 已有代码 |
| 自身 module | `github.com/stones-hub/taurus-x`（可 `go install ...@latest`） |
| 默认功能 | 基础后台底座：登录/JWT/CSRF/限流 + 用户/角色/权限/部门 RBAC + 登录/访问/操作/前端错误日志 + 个人中心 + 首页 |
| 前端 | Vue3 + TS + Vite + Element Plus + Pinia，必带，不可取消 |
| 必选组件 | taurus-pro-common、taurus-pro-config、taurus-pro-http、taurus-pro-storage（底座依赖 DB+Redis） |
| 可选组件 | taurus-pro-consul、taurus-pro-opentelemetry、taurus-pro-tcp、taurus-pro-grpc、taurus-pro-milvus |
| 可选组件生成程度 | 只接入：配置文件 + 初始化/关闭代码 + 组件容器字段 + go.mod 依赖；不带业务示例 |
| 交互方式 | 只做交互式，不提供 `--with` 等组件参数 |
| 生成后动作 | 自动 `go mod tidy` + 生成 Wire 代码；前端只提示执行 `pnpm install` |
| 上线形态 | 与 admin 一致：一个 Go 进程同时提供接口和前端页面（前端打包产物由 Go 返回），一个端口 |
| 工程配套 | Makefile、Dockerfile + docker-compose、docs 规范文档 + README、初始化 SQL |
| CRUD 模块生成器 | 第一版不做 |
| 编码执行器 | Claude Code；Pi 写方案/任务书并独立验收 |

## 3. 使用方式

```
taurus-x new myproj
```

交互过程：

1. Go module 路径（默认 `github.com/stones-hub/myproj`，可改）
2. 输出目录（默认 `./myproj`；目录已存在且非空时报错退出，不覆盖）
3. 组件多选：4 个必选组件显示为已选且不可取消，5 个可选组件默认不选
4. 显示汇总，确认后生成

生成后自动执行：`go mod tidy`、Wire 代码生成（用 `go run github.com/google/wire/cmd/wire`，不要求全局装 wire）。
任一步失败时明确报错，并保留已生成的文件让用户排查，不自动删除。
最后打印下一步命令（初始化数据库、`pnpm install`、`make dev`）和初始管理员账号说明。

另有 `taurus-x version`。第一版不做其他子命令。

## 4. 生成的项目结构

```
myproj/
├── backend/
│   ├── bin/main.go                 # 入口
│   ├── app/                        # controller/service/repo/model/dto/middleware/helper/constants/routes/hooks/crontab/command
│   │   ├── bootstrap.go
│   │   └── wire.go / wire_gen.go
│   ├── internal/taurus/            # 框架组件容器：按所选组件生成 Provide* 函数和 Components 字段
│   ├── internal/wire/              # provider set 自动扫描器（沿用 admin）
│   ├── config/config.yaml
│   ├── config/autoload/            # http/db/redis/logger/cron 必有；consul/otel/tcp/grpc/milvus 按选择生成
│   ├── .env.example
│   ├── Makefile
│   └── go.mod / go.sum
├── frontend/                       # admin 前端裁剪：login/home/user/role/permission/dept/log/profile
├── docs/                           # 项目规范、后端开发流程、前端开发流程、部署文档
├── scripts/sql/init.sql            # 底座表 + 底座权限菜单 + 初始管理员
├── Dockerfile / docker-compose.yml / .dockerignore / .gitignore
├── Makefile
└── README.md
```

替换规则：项目名替换二进制名、`app_name`、默认库名、容器名、前端标题、README/文档中的项目名；module 路径替换所有 Go import。

## 5. 后端底座来源与裁剪

以 admin 当前代码为模板来源，保留：

- controller/service/repo/model/dto：auth、user、role、permission、dept、log（访问/操作/前端错误）、login_log、index
- middleware：全部（access_log、auth、csrf、host、jwt、log_common、operation_log、password_change_validator、permission、rate_limit）
- helper：只保留底座用到的（crypto、validate、query、verification_code、permission、store、code 等）；
  去掉发票、LibreOffice、邮件发送、Excel 等业务 helper
- routes：只注册底座路由 + 健康检查 + 前端页面回退

去掉：CRM、需求/方案/合同/订单、资源/采购、财务、任务、区位、邮件、发票模板与 `assets/` 中的业务文件，以及对应依赖（excelize、gomail 等）。

## 6. 可选组件接入方式

`internal/taurus/wire.go` 和 `Components` 结构按选择生成。每个可选组件：

- 在 `config/autoload/<组件>/` 生成配置，带 `enable` 开关，敏感值和地址走 `${VAR:default}` 环境变量
- 在 `internal/taurus` 生成 `ProvideXxxComponent`（初始化 + cleanup），未启用时返回 nil
- tcp/grpc 是独立服务端口：在 bootstrap 中与 HTTP 一起启动、一起优雅关闭；Dockerfile/compose 暴露对应端口
- consul：服务注册/注销
- otel：初始化 tracer provider，关闭时 flush
- milvus：创建客户端
- docker-compose：选了 consul 增加 consul 服务；选了 milvus 增加 milvus standalone（含其依赖 etcd、minio）；otel 只配置上报地址，不内置收集器

组件版本由 taurus-x 内置注册表固定（以本机模块缓存和 admin 当前使用的版本为准），生成的 go.mod 只包含所选组件。

## 7. 前端

从 admin `frontend/` 裁剪：保留 login、home、user、role、permission、dept、log、profile 页面，
`PermTree`、`SidebarMenu` 等底座组件，`api/` 中底座接口；去掉业务页面、业务组件和业务接口。
开发时 Vite `/api` 代理到后端端口；生产构建 `VITE_API_BASE_URL` 为空，由 Go 返回页面。
前端文件原样复制，只对 `package.json`、`index.html`、`.env*` 中的项目名做替换（避免与 Vue 的 `{{ }}` 冲突，
只有 `.tmpl` 后缀的文件才走模板渲染）。

## 8. 初始化 SQL 与初始管理员

`scripts/sql/init.sql` 只含 12 张 `admin_*` 底座表、底座菜单/按钮权限、超级管理员角色和一个初始管理员。
初始账号与默认密码写在生成项目的 README 中，并提示登录后立即修改。
admin 现有 `password_change_validator` 只做"改密码后旧 token 失效"，没有"首次登录强制改密码"，第一版不新增该功能。

## 9. taurus-x 自身结构（建议）

```
taurus-x/
├── main.go
├── internal/cli/          # new、version 命令与交互
├── internal/components/   # 组件注册表：名称、包路径、版本、是否必选、描述
├── internal/generator/    # 渲染 embed 模板、写文件、执行 tidy/wire
├── templates/             # 项目模板（embed）
└── docs/ README.md AGENTS.md CLAUDE.md HANDOVER.md
```

生成逻辑做成可直接调用的函数（输入：项目名、module、目录、组件列表），交互层只负责收集输入；
这样自动化测试可以绕过交互直接测各种组件组合。

## 10. 验收方式

1. taurus-x 自身：`go vet ./...`、`go test ./...`（覆盖：只选必选、全选、典型组合三种情况生成后 `go build ./...` 通过）
2. 生成"全选"项目：`go build`、`pnpm install && pnpm build` 通过
3. 本机运行：Docker 起测试 MySQL/Redis，导入 `init.sql`，启动生成的项目（只监听 127.0.0.1），
   `/health` 正常；独立测试浏览器登录、打开用户/角色/权限/部门/日志页面，控制台无报错
4. 交互流程：在终端真实走一遍 `taurus-x new`
5. 验收后停止进程、删除测试容器和 /tmp 下生成的测试项目

- 本机未全局安装 pnpm（admin 当时用 `npm exec` 临时提供 pnpm 10.34.7），前端验收沿用该方式，不全局安装。
- T2 附加范围已确认：随机初始管理员密码、示例配置不携带实际 JWT 密钥、部门空编码重复问题、普通用户自行改密权限边界、downloads 残留及 EOF 空行清理。不新增首次登录强制改密。详细任务与验收见 `.pi/tasks/T2-security.md`；T2 任务书和验收要求已确认，已获编码授权（不含 commit/push/发布）。
